1. What is the CAE Platform?

Think of the CAE (Continuous Audit Engine) as an always-on robot auditor that watches your company's financial transactions 24 hours a day, 7 days a week — and immediately alerts you when something looks wrong.

Before CAE: A CA firm audits your books once a year. By the time they find a problem, it is already 12 months old and the damage is done.

With CAE: The same 100+ audit checks run every single day. The moment a duplicate invoice appears, or a salary is paid to a terminated employee, or a bank account is changed just before a payment — you get an alert within 24 hours.

Without CAEWith CAE
Annual audit onlyDaily automated checks
Problems found after 12 monthsProblems found within 24 hours
Manual exception tracking in ExcelAutomated workflow with AI explanations
No real-time risk scoreLive risk score updated every day
GST reconciliation done manuallyAuto-reconciled daily

2. What You Need Before Starting

Computer Requirements

Windows 10/11, Mac, or Linux
At least 8 GB RAM
10 GB free disk space
Internet connection

Software to Install First

Docker Desktop (free)
Git (free)
A web browser (Chrome, Firefox, Edge)

How to Install Docker Desktop (the most important step)

1

Go to Docker's website

Open your browser and go to: https://www.docker.com/products/docker-desktop

2

Download and Install

Click "Download for Windows" (or Mac). Run the installer. Restart your computer when asked.

3

Verify Docker is Running

After restart, you should see a Docker whale icon in your system tray (bottom right on Windows). That means Docker is running.

What is Docker? Docker is like a "virtual computer inside your computer." The CAE platform runs inside Docker so you do not need to install databases, Python, Node.js, or anything else separately. Docker handles everything automatically.

3. How to Install and Open the Platform

1

Open Terminal / Command Prompt

Windows: Press Windows + R, type cmd, press Enter.
Mac: Press Cmd + Space, type Terminal, press Enter.

2

Download the CAE Code

Type the following command and press Enter:

git clone https://github.com/khatrisagar27-hub/Claude-.git cd Claude-
3

Go to the CAE Folder

cd cae
4

Start the Platform

This one command starts everything — the database, the web server, everything:

docker-compose up -d

The first time, this takes 5–10 minutes because it downloads all required components. After that it starts in under 1 minute.

5

Load Sample Data (First Time Only)

This creates a demo Indian manufacturing company with 2 years of real-looking data:

python scripts/seed_data.py python scripts/run_first_audit.py
6

Open the Platform in Your Browser

Open Chrome/Firefox and go to:

http://localhost:3000

You should see the CAE login screen.

To STOP the platform (when you are done for the day), type in the terminal:
docker-compose stop

To START it again the next day:
docker-compose start

6. Exceptions — Seeing What Went Wrong

URL: http://localhost:3000/exceptions

An exception is any transaction or event that broke a control rule. For example: a duplicate invoice, a payment made without a PO, or a salary paid to someone who was terminated.

How to use the Exceptions page:

1

Filter by Severity

Use the filter buttons at the top to show only CRITICAL or HIGH exceptions. Start with Critical.

2

Filter by Business Area

You can filter by Purchases, Sales, Inventory, Payroll, Journal Entries, Treasury. Useful if you manage one department.

3

Click on an Exception

Click any exception to open the detail view. You will see exactly which transactions are involved, the financial impact in rupees, and the evidence.

4

Get AI Explanation

Click "Get AI Explanation." The platform uses Claude AI to explain the exception in plain English — what happened, why it's risky, and what questions to ask management.

5

Raise a Management Query

Click "Raise Query" to send a formal question to the responsible person. Set a due date. They will receive it in their inbox.

6

Mark as False Positive

If after review the exception is not actually a problem (e.g., system generated it in error), you can mark it as "False Positive" so it does not appear again.

Exception Status Flow:

Open → Query Sent → Responded → Resolved / Escalated / Closed

7. Management Queries — Asking Your Team

URL: http://localhost:3000/queries

A Management Query (MQ) is a formal question the auditor sends to the responsible person in management — like an accountant, purchase manager, or HR head. This creates a documented, traceable record of the question and answer.

How to create a Query:

  1. Go to an Exception detail page
  2. Click "Raise Management Query"
  3. The system auto-fills a question based on AI analysis
  4. Select the person responsible (e.g., Purchase Manager)
  5. Set a due date (e.g., 7 days from now)
  6. Click Send

What happens next:

  • The assigned person sees the query in their My Queries inbox
  • They type their response and attach supporting documents
  • You review the response and either close the query or escalate it
  • The entire thread is saved permanently for audit trail

Query Status Meanings:

StatusMeaning
OpenQuestion sent, waiting for response
RespondedManagement has replied, auditor needs to review
EscalatedResponse not satisfactory, raised to senior management
ResolvedExplanation accepted, issue closed
ClosedFully completed and archived
Overdue Queries: If a query passes its due date without a response, the system flags it red on the Dashboard under "Overdue Queries." The auditor should follow up or escalate.

8. Remediation Tracker — Fixing the Problems

URL: http://localhost:3000/remediation

Once an exception is understood, someone needs to fix the root cause. The Remediation Tracker records what action was taken, who is responsible, and by when.

How to add a Remediation Action:

  1. From the Exception detail page, click "Add Remediation Action"
  2. Describe the root cause (e.g., "Purchase team bypassed PO approval for urgent orders")
  3. Write the action plan (e.g., "Implement mandatory PO approval in ERP before invoice entry")
  4. Assign to a responsible person
  5. Set a target completion date

Retest Feature:

After the action is implemented, the auditor can run a Retest. The system re-runs the same audit rule to check if the problem has been fixed. The retest result is recorded as: Effective / Partially Effective / Ineffective.

10. Risk Heatmap — Visualising Your Risk

URL: http://localhost:3000/risk

The Risk Heatmap is a coloured grid that shows which part of your business is most risky. Rows are business processes (Purchase, Sales, Inventory, Payroll, Treasury). Colours range from green (low risk) to red (critical risk).

How the Risk Score is Calculated:

Risk Score = Likelihood × Impact × Materiality × Frequency × (1 + Control Weakness) Where: Likelihood = How often has this type of exception happened? (1–5) Impact = How much money is at risk? (1–5) Materiality = Is the amount significant vs. company turnover? (0.5–2.0) Frequency = How often does this control run? (1–3) Control Weakness = Are controls strong or weak? (0 = strong, 1 = none) Score Bands: 0–20 = Low (Green) 21–50 = Moderate (Yellow) 51–80 = High (Orange) 81–100 = Critical (Red)

The score is recalculated every day at 3 AM automatically so the heatmap always shows your current risk position.

Risk Trend:

Below the heatmap is a 30-day trend line showing whether your average risk score is going up or down. A downward trend means your remediation actions are working.

11. GST Reconciliation

URL: http://localhost:3000/gst

This module compares what your company filed with the GST portal against what is in your accounting books. Differences can mean tax liability, penalties, or lost ITC (Input Tax Credit).

What it checks:

ComparisonWhat It Means
GSTR-1 Turnover vs. Books TurnoverDid you report more or less sales to GST than what is in your books?
GSTR-2B ITC vs. Books ITCAre you claiming more input tax credit than your suppliers reported?
GSTR-3B ITC vs. GSTR-2B ITCDid you actually claim what you were eligible for?

How to use:

  1. Upload your GSTR-2B JSON file (download from GST portal)
  2. The system matches it against your purchase register automatically
  3. You see a table showing every month's variance
  4. Months with high variance are flagged red with the Rs. risk amount

12. Fraud Analytics

URL: http://localhost:3000/fraud

This is the most advanced section. It uses statistical and AI techniques to find patterns that suggest fraud — even when individual transactions look normal.

What it detects:

TechniqueWhat it Finds
Benford's Law Checks the first digit of all invoice amounts. Genuine data follows a specific pattern. If your data doesn't follow it, someone may be fabricating amounts. You see a bar chart showing actual vs. expected distribution.
Duplicate Detection Finds invoices that are slightly different but suspiciously similar — same vendor, similar amount (within 1%), similar date (within 3 days). Catches "near-duplicate" payments that exact matching misses.
Round Amount Analysis Flags transactions that are exactly Rs.1,00,000 or Rs.5,00,000 or Rs.10,00,000. Real business transactions are rarely such round numbers — manual manipulation often creates them.
Behavioural Anomaly (ML) An AI model learns the normal posting pattern of each user (time of day, amount range, accounts used). Transactions that deviate significantly from a user's normal pattern are flagged.
Month-End Spike Detection Detects unusual surges in transactions in the last 3 days of a month — a classic sign of revenue manipulation to hit targets.

13. Data Ingestion — Uploading Your Company's Data

URL: http://localhost:3000/ingestion

The platform needs your financial data to run audit rules. You can upload data in two ways:

Option A: Upload Excel / CSV File

1

Go to Data Ingestion page

Click on "Data Ingestion" in the left sidebar

2

Select the Data Type

Choose what you are uploading: Sales Invoices, Purchase Invoices, Journal Entries, Bank Transactions, Inventory, or Payroll

3

Upload the File

Drag and drop your Excel or CSV file. The system automatically maps columns and imports the data. Errors are shown row by row.

4

Trigger Audit Run

After upload, click "Run Audit Now" to immediately run all rules on the new data.

15. Common Questions (FAQs)

Q: The platform is not opening at http://localhost:3000

A: Make sure Docker is running (check the whale icon in system tray). Then type docker-compose up -d in the terminal again and wait 30 seconds.

Q: I see "No exceptions found" even after running the audit

A: The seed data script must be run first: python scripts/seed_data.py followed by python scripts/run_first_audit.py

Q: Can I use my own company's data instead of demo data?

A: Yes. Go to Data Ingestion (http://localhost:3000/ingestion) and upload your Excel files. Prepare your data in the column format shown in Section 13.

Q: How often does the audit run automatically?

A: By default, rules run at 2 AM every day. You can also trigger a manual run any time from the Data Ingestion page by clicking "Run Audit Now."

Q: Who should use which role?

PersonRecommended Role
CA / External AuditorPartner or Auditor
CFO / Finance HeadCFO
Purchase ManagerProcess Owner (Purchase)
HR ManagerProcess Owner (Payroll)
IT AdministratorSuper Admin

Q: Is data safe? Can others on the internet see it?

A: No. The platform runs completely on your own computer (localhost means "this computer only"). No data is sent to the internet. Only people on your local network can access it.

Q: How do I add a new company / client?

A: Log in as Super Admin → Go to Settings → Companies → Add New Company → Fill in company details including GSTIN, PAN, and sector.

Q: The AI explanation is not working

A: The AI explanation requires an Anthropic API key. Go to Settings → Configuration → add your API key from https://console.anthropic.com
