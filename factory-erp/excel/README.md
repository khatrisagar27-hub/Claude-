# Factory ERP — Excel edition

Macro-free alternative to `factory-erp/backend` + `factory-erp/frontend`:
one workbook, no server, no Docker. Built for the case where a client's
team just wants to open a file and log stock, machines, and production —
not stand up infrastructure.

## What's in it

`FactoryERP.xlsx` (generated by `build_workbook.py` — see that file for the
full design notes):

- **Master data**: Machines, Products, BOM
- **Append-only logs**: StockMovements, Downtime, WorkOrders, Rejections
- **Analytics** (`Analytics_*` sheets): on-hand qty, stock ageing/reorder/
  valuation, OEE, downtime Pareto, production summary, material yield/cost
  per unit — every formula computed the same way as
  `factory-erp/backend/app/analytics/*.py`, so the two editions agree on
  what a number means
- **Dashboard**: KPI cells + charts
- **README** sheet inside the workbook itself: color legend, how to add
  data, and — importantly — the honest limits of doing this in Excel for
  multi-user editing (OneDrive/SharePoint co-authoring is the ceiling, not
  a database)

Pre-seeded with the same demo scenario as `backend/scripts/seed_data.py`
(one plant, two presses, a steel-coil→bracket BOM, one completed work order
with downtime and a rejection) — every Analytics number in the workbook was
checked against the backend's numbers for that same scenario and matches
exactly.

## Regenerating it

```bash
cd factory-erp/excel
pip install openpyxl
python build_workbook.py          # writes FactoryERP.xlsx
```

Formulas are written as strings (as any script-generated workbook must be)
and get their cached values from Excel itself on first open — or run
recalc.py from Anthropic's `xlsx` skill against the file to verify/populate
them ahead of time.

## Why this exists instead of just the web app

This is a genuine architectural fork, not a lesser version of the same
thing — see `factory-erp/README.md` for the tradeoffs (no true concurrent
writes, no roles/API, but zero hosting and a format the client's team
already knows). Pick this when that tradeoff is the right one; pick the
FastAPI/Postgres edition when it isn't.
